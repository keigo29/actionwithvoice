# Ray（レイ・デスク常駐型の音声アシスタント・無料版）

机の前で、Mac のマイクとスピーカーだけで話しかけられるアシスタントです。頭脳は Claude Code（`claude -p`、Pro の枠）で、Cmd のローカルクローンを作業場所にして動きます。**追加の料金はかかりません**（API キーは使いません）。設計メモは Cmd の `Notes/音声連携.md` の「デスク常駐型アシスタント（ROSE 風）」にあります。

```
右 Option を押している間に話す（またはウェイクワード）
→ 録音 → Whisper（Mac の中で文字にする）
→ claude -p（作業場所は Cmd。返事は短く・記号なし）
→ 1文できるたびに読み上げ ＋ 光る円の画面に表示（Claude の返事も、全部書き終わるのを待たない）
→ Q&A を Cmd の Data/ray/ に置いてコミット。push はまとめて（デイリーには書き足さない）
```

## できること（例）

- 「Cmd で一番大きいフォルダは？」「今日のデイリー読んで」「Inbox に牛乳を買うを追加して」
- 「git の状態教えて」「このプロジェクトのテスト回して」
- 続けて話すと前の話の続きになります（5分以内）。「新しい話」で切り替え
- 話している途中でもキーを押せば止まって、次を聞きます

## 振り分け（ローカル → Gemini 無料枠 → Claude）

Cmd の `Notes/音声連携.md` の「振り分けとフォールバック」「プライバシーの線引き」のとおりに、質問ごとに答える頭脳を選びます。

| 質問 | 順番 | 画面 |
|---|---|---|
| あいさつ・一般知識・計算・翻訳 | ローカル → Gemini → Claude | なし |
| 「詳しく」 | Gemini → Claude | なし |
| 調べもの・ニュース・値段・店・「近くの〜」 | 検索 API（Tavily）→ 要約は Gemini → Claude | 調べたページの一覧 |
| 比べる・まとめて調べる（深い検索） | Gemini（グーグル検索つき）→ Claude | 調べたページの一覧 |
| 体調・体重・気分・習慣・筋トレ | Ray が Cmd の記録を読んで、ローカル → Gemini → Claude | 体重・気分のグラフ／習慣のマス目／筋トレ |
| お金・仕事・予定・メモ・ファイルの作業・天気・朝のまとめ | Claude だけ | Claude が選ぶ |

- ローカル（Ollama、既定は `qwen2.5:7b`）は Mac の外に出ません。文ができるたびに読み上げます。Ray が動いている間はメモリに載せたまま（約 5GB）で、止めると外します
- Gemini は無料枠だけを使います（Flash-Lite、1日450回で止める。上限のエラーが出たら日本時間17時まで Claude）。お金・仕事・予定・メモと、Claude が答えたやり取りは Gemini に渡しません
- ローカルや Gemini が自分では無理と判断したとき（「@クロード」と返させる）、止まっている・遅いときは、次の段に回します
- 同じ会話の中なら、どの頭脳が答えた分も引き継ぎます。ログの JSON の `brain` に、どれが答えたかを残します

### 検索の受け皿（調べもの）

Gemini の検索の枠は早く無くなるので、ふだんの調べものは検索 API で結果を取ってから要約します（`ray/search.py`。Cmd の `Notes/音声連携.md`「検索の受け皿」）。

1. **取る**：Tavily の基本検索（1回1クレジット。無料で月1,000クレジット。月950回で止めます）。「近く」は `[search] near` の場所の名前に置き換えます（空なら `[weather] place`）。「その店の営業時間」のような続きの質問は、前の検索の言葉を足します
2. **要約**：上位5件を Gemini 無料枠（Flash-Lite、グーグル検索は使わない）に渡し、3文以内・記号なし・日本語で答えます。結果にある実在の名前だけを使い、無いものは作らせません
3. **だめなとき**：Gemini の枠が無い・止めてある・要約に失敗したら、Claude（WebSearch）が答えます。Gemini が使えないときは、Tavily も呼びません（枠を減らさない）。ローカル 14B は使いません
- 比べる・まとめて調べるような深い検索と、Tavily の鍵が無い・枠が無い・結果が無いときは、これまでどおり Gemini の検索 → Claude
- 外に出るのは検索の言葉と公開の検索結果だけです。予定・家計・メモなど持ち主のデータの言葉がある質問は、振り分けで Claude に行くので、検索には来ません
- 鍵は環境変数 `TAVILY_API_KEY` か `config.toml` の `[search] api_key`。ログや Cmd には書きません
- ログの JSON の `search` に、経路（`route`：`tavily+gemini` / `gemini_search` / `claude`）、検索の言葉（`query`）、結果のタイトルと URL（`results`）、失敗の理由（`error`）を残します
- 検索 API は `SEARCHERS` で差し替えられます（Exa などを足すときは、同じ形の関数を1つ足す）

### プロンプト変換（Claude に回す前）

Claude 行きと決まった質問のうち、**長い発話**（60字以上）か**長い履歴**（同じ会話で4回以上、または合わせて1200字以上）のときだけ、短い依頼に直してから Claude に渡します。短い質問は原文のままです。流れは「**抽出はコード → 整形は 7B → 検証はコード**」です（Cmd の `Notes/音声連携.md`「プロンプト変換はコードで支える」）。

0. **テンプレ（コードだけ）**：決まった形でくり返す頼みごとは、中身をコードで抜き出して決まった依頼にします（`ray/templates.py`）。当たったら 7B は呼びません。短い質問にも使います（待ちが増えないため）。中身まで抜き出せないもの（「これを追加して」など）は、下の流れに任せます
   - やることの追加：行き先は Inbox（「AIに頼みたいこと」は `Notes/AIに頼むこと.md`、「副業のタスクに」ならそのプロジェクト）。「〜までに」があれば `📅`
   - 記録：睡眠（「4時に寝て7時半に起きた」→ `- 睡眠 4:00-7:30 3.5時間`）・気分（`- 気分 4/5`）・体重（`- 体重 70.5kg`）を、その日のデイリーの `## メモ` に
   - 予定の確認：読む日のデイリー（今日・「次の予定」は今日と明日・「今週」は7日分）と、何を答えるか。読むだけ
1. **抽出（コード）**
   - 先に見るファイル：言葉と Cmd のファイルの対応ルールで決めます（`ray/local.py` の `REF_RULES`。振り分けルールの続き）。例：体重 → 体の記録と減量、家計・残高 → `Data/kakei.json`、予定 → 今日のデイリー、「来週の水曜」「11月20日」→ その日のデイリー。Cmd に無いファイルは添えません
   - 下ごしらえ：「えーっと」「あのー」「〜と思うんだけど」、呼びかけの「レイ」、くり返し、「水曜、いや木曜」の言い直しを、ルールで落とします（`ray/rewrite.py` の `tidy`）
2. **整形（7B）**：意味を保った言い換えと、履歴の要約だけ。Ollama の `format`（JSON スキーマ）で形を固定します
3. **検証（コード）**：変換前の数字（漢数字・全角も数に直して比べる）・日付の言葉・曜日・英語の名前が、変換後に残っているかを照合します
   - 欠けていたら、**原文を併記**して送ります
   - 壊れた JSON・空・日本語でない・元に無い数字を作った・長くなった・10秒で終わらない・ローカルが載っていない、なら**原文のまま**送ります

- 履歴を要約したときは、Claude のセッションを続けずに要約を渡して新しく始めます（履歴とファイルの読み直しを減らすため）
- 変換は Mac の中（Ollama）だけで行います。しきい値は `ray/rewrite.py` の定数で、`config.toml` の `[rewrite]` で上書きできます
- ログの JSON の `rewrite` に、変換したか（`applied`）、理由、**変換前後の組**（`before` / `after`）と字数、下ごしらえした文（`tidied`）、使ったテンプレ（`template`）と抜き出した中身（`slots`）、添えたファイル（`refs`）、欠けた固有情報（`missing`）、原文を併記したか（`with_original`）、かかった時間（`ms`）、失敗の理由（`error`）を残します

準備：
- ローカル：`brew install ollama` → `ollama pull qwen2.5:7b`。使わないなら `config.toml` の `[local]` を `enabled = false`
- Gemini：Google AI Studio で、**課金を設定していないプロジェクト**の API キーを作り、環境変数 `GEMINI_API_KEY` か `config.toml` の `[gemini] api_key` に入れる。鍵が無ければ Gemini の段は飛ばします
- 検索：Tavily に登録（カード不要）して API キーを作り、環境変数 `TAVILY_API_KEY` か `config.toml` の `[search] api_key` に入れる
- `python -m ray --check` で確かめられます

## プロンプトの効率を確かめる

`python -m ray --prompt-report`（`--days 30` で日数を変える）で、Cmd の `Data/ray/` の記録から、送った量と無駄の目安をまとめます（`ray/promptcheck.py`）。

- Claude：毎回読む量（入力トークン。キャッシュに書いた分・読んだ分）、往復の回数、使った道具、時間。ログの JSON の `usage` に1回ずつ残します
- Gemini：入力・出力のトークン
- 言い換え（7B）：待ち時間、失敗の割合、減った字数
- 最後の「気になるところ」に、目安（`promptcheck.py` の頭の定数）を超えたものと対策を出します

測って分かったこと（2026年11月）
- Claude は「こんにちは」だけでも約2.5万トークン読みます。ほとんどは Claude Code の決まった部分（道具の説明など）で、送る文は50トークンほどです。`[claude] tools` で Ray が使う道具だけにして、約1.2万に半減しました
- 7B の言い換えは平均6.6秒・4割近く失敗し、依頼はむしろ長くなっていました。今は長い発話（60字以上）のときだけ 7B を使います。長い履歴だけのときは、7B を呼ばずにセッションを続けます。先に見るファイルは、7B を使わないときもコードで添えます（`[rewrite] llm_reasons`・`refs_always`）

## Ray から声をかける（朝・予定の前・夜）

話しかけなくても、毎日かならず通る場面で Ray のほうから話します（`ray/routine.py`）。どれも Claude を呼ばず、コードだけで作ります。

| いつ | 何を話すか |
|---|---|
| 朝（5時〜11時に、はじめて机にいると分かったとき） | 天気 → 今日の予定 → 期限が3日以内のやること。ゆうべの睡眠がデイリーに無ければ「何時に寝て、何時に起きましたか？」と聞いて、答えを記録する |
| 予定の10分前 | 「あと10分で、19時から、飲み会です」とカレンダーの画面 |
| 夜（22時から） | 「今日の気分は、5段階でいくつですか？」と聞いて、答えを記録する（もう書いてあれば聞かない） |

- 聞いたあとは、ボタンなしで少しのあいだ聞きます。キーを押して答えてもかまいません（3分まで）。「4」「4かな」「2時に寝て8時に起きた」のように答えると、デイリーの `## メモ` に書きます。答えでない話をすれば、ふつうの質問として扱います
- 机にいるかは、Mac をさわっていない時間で見ます（3分以上さわっていなければ、いないとみなして話さない）。戻ってきたら話します。予定の知らせは、始まったら言いません
- 会話の途中・話している途中は、終わるまで待ちます
- 「今日は静かに」で、その日はもう声をかけません。「声かけして」で戻ります
- 同じ日に同じ声かけは1回だけです（Ray を起動し直しても `routine-state.json` で覚えています）
- 「おはよう」「朝のまとめ」と言ったときも、同じまとめを Claude を呼ばずに話します
- 時刻や、どれを使うかは `config.toml` の `[routine]` で変えられます（`config.example.toml` を参照）

## 決まった頼みごとは Ray が自分で片づける（Claude を呼ばない）

「牛乳を買うをやることに追加して」「体重70.5キロって記録して」「今日の予定は？」のような決まった頼みごとは、Claude を呼ばずに Ray が自分で Cmd に書く・読んで話します（`ray/actions.py`）。Claude は1回呼ぶだけで約1.2万トークンを読むので、トークンを使わず、すぐ終わります。

| 頼みごと | Ray がすること |
|---|---|
| やることの追加 | `Inbox.md` の末尾に `- [ ] 中身`（「AIに頼みたいこと」は `Notes/AIに頼むこと.md` の `## 頼みたいこと`、「副業のタスクに」なら `Projects/副業.md` の `## タスク`）。「〜までに」があれば ` 📅 日付` |
| 体の記録 | その日のデイリーの `## メモ` に `- 体重 70.5kg`・`- 気分 4/5`・`- 睡眠 4:00-7:30 3.5時間` |
| 予定の確認 | デイリーの `## 予定` などから集めて読み上げ、カレンダーの画面を出す（読むだけ） |

- 当てはまるかどうかは、プロンプト変換のテンプレ（`ray/templates.py`）と同じ決まりで見ます。中身まで抜き出せたときだけ Ray が片づけます
- 「取り消して」と言うと、直前（10分以内）に Ray が足した行を消します
- 書く前に Cmd を最新にし（`git pull`）、書いたファイルだけをコミットします。push は会話のログと一緒にまとめます
- 書く先のファイルや見出しが無い・「これを追加して」のようにあいまい・予定を変える話は、これまでどおり Claude に回します
- `[actions] enabled = false` で、前の動き（全部 Claude）に戻せます。`--prompt-report` に、Ray が自分で片づけた件数が出ます

## push はまとめる

会話のログと Ray が書いたファイルは、書いたらすぐコミットし、push は最後に書いてから60秒あと（`[log] push_delay`）に1回にまとめます。会話の途中（Claude が Cmd で git を使っているかもしれないとき）は、終わるまで待ちます。Ray を止めるときは、残りをすぐ送ります。取り込みでぶつかって止まったら、元に戻して次の機会にもう一度送ります。

## 定番の返事（毎回同じでよいもの）

自己紹介のように毎回同じでよい返事は、用意しておいたものをそのまま使います。Claude も Gemini も呼ばないので、すぐに答えます（`ray/canned.py`）。

- 1つの返事が1つの `.md` です。頭に `match:`（当てる言い方の正規表現）と `max_chars:`（これより長い発話には当てない。既定20字）、`---` のあとに本文を書きます
- 本文は Claude の返事と同じ形です。`@画面 diagram {...}`（Mermaid の図）や `@画面 steps {...}`（スライド）の行で、画面も一緒に出せます
- 置き場所：Ray に最初から入っているものは `desk/ray/canned/`（今は `自己紹介.md`）。声で保存したものは Cmd の `Data/ray/canned/`（持ち主のデータを含みうるので Cmd に置きます）
- 「今の答えを定番にして」と言うと、直前の答えを、同じ言い方で聞かれたら返す定番として保存します
- 「自己紹介を直して」のように、変える・直す話は定番で答えず、いつもの振り分けに回します
- ファイルは聞かれるたびに読むので、書きかえたら起動し直さなくても次から変わります

## 安全のための決まり

| 区分 | 中身 |
|---|---|
| 確認なしでしてよい | 読む・調べる（Read / Grep / ls / du など）、Cmd のファイルの編集、git の status / diff / log / add / commit / pull / push（main へのふつうの push）、テストの実行 |
| 「確認です。〜よいですか？」と聞いてから | 上以外のコマンド全部（削除、ほかのリポジトリへの操作など）。「はい」で実行、「いいえ」でやめる |
| 確認されてもしない | `sudo`、強制 push、`git reset --hard` |

画面の円が赤く点滅していたら、確認の返事を待っています。

## はじめの設定（Mac・1回だけ）

1. **Claude Code**：`npm i -g @anthropic-ai/claude-code` → `claude` を1回起動して Pro のアカウントでログイン
2. **Cmd のクローン**：`git clone https://github.com/keigo29/Cmd.git ~/Cmd`（push できる状態にしておく）
3. **Python の準備**（このフォルダで）
   ```sh
   python3 -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   cp config.example.toml config.toml   # 必要なら中身を直す
   ```
   - Apple Silicon なら mlx-whisper が入ります（最初の1回だけモデルをダウンロード）
   - Intel Mac などは whisper.cpp を使う：`brew install whisper-cpp` ＋ モデル（`ggml-medium.bin` など）を `~/models/` に置き、`config.toml` の `[stt] engine = "whisper_cpp"`
4. **読み上げの声**：システム設定 → アクセシビリティ → 読み上げコンテンツ → システムの声 → 管理 で「Kyoko（拡張）」を入れると自然になります
5. **確認**：`python -m ray --check`（全部 ✅ になれば OK）

## 動かす

```sh
cd desk && source .venv/bin/activate
python -m ray                              # 常駐。ブラウザに円の画面が開く
python -m ray --text 今日のデイリー読んで     # マイクなしで1回だけ試す
```

最初に起動したとき、macOS が次の許可を求めます。ターミナル（または使っているアプリ）に許可してください。

- **マイク**（録音のため）
- **入力監視**（キーを押している間を知るため。システム設定 → プライバシーとセキュリティ → 入力監視）

### ダブルクリックで起動する（Ray.app）

```sh
./make-app.sh        # ~/Applications/Ray.app ができる（1回だけ。このフォルダを動かしたら作り直す）
```

- Ray.app をダブルクリックすると、ターミナルの新しい窓で `python -m ray` が動きます（venv の有効化はいりません）。Dock に入れておくと便利です
- すでに動いているときは、もう1つは起動せず、状態の画面を開くだけです
- 止めるときは、その窓で Ctrl+C（窓を閉じても止まります）
- マイク・入力監視の許可は、ターミナルに出したものをそのまま使います

ログインしたら自動で起動させたいときは、「自動化」の「ログイン項目」にシェルスクリプトを登録するか、launchd を使います（必要になったら足す）。

## 画面を見せながら話す

予定・数字・一覧・出典があるときは、話している内容に合わせて画面に絵を出します（プレゼンのように、場面ごとに進む）。要件は Cmd の `Notes/Ray画面表示.md` にあります。

| 種類 | 画面 | データ |
|---|---|---|
| calendar | 日・週・月のカレンダー。話している予定を光らせる | デイリーの `## 予定`、`## YYYY-MM-DD` の下、`📅` の期限、`#節目` |
| note | ノートの抜き出し。根拠の行に印 | Cmd のノート |
| todos | 期限の近い順のやること（期限切れは赤）、プロジェクトの進み具合 | `- [ ]`、`Projects/` |
| habits | 毎日確認のマス目と、続いている日数 | デイリーのプロパティ、`Notes/毎日確認.md` |
| body | 体重・気分の折れ線グラフ（目標の線つき） | デイリーの `- 体重`・`- 気分`、`Data/health/` |
| kakei | カテゴリ別の支出、予算の残り | `Data/kakei.json` |
| workout | 種目ごとの重さの推移、今日のメニュー | `Data/kintore/sets.csv` |
| weather | 1時間ごとの天気 | open-meteo（30分は使い回す） |
| diff | 変えたファイルの前と後、git の状態 | Cmd の git |
| web / sources | ページの写真と引用カード、使ったページの一覧 | WebSearch・WebFetch |
| table / steps / calc | 比較の表、1つずつ進む手順、式と答え | Claude が考えた中身 |
| diagram | 仕組み・流れ・関係の図（Mermaid：フローチャート・シーケンス図・マインドマップ・タイムライン・ガントなど）。話している所のノードを光らせる | Claude が書いた Mermaid。ライブラリは Workstation から写した手元のもの（11.17）。無いときだけネットから |
| diagram（図解） | Workstation の図解と同じ形の図（四角・ひし形・データベース・アイコンの箱・枠・ER図のテーブル・クラスなど）。話している所の図形を光らせる | Claude が書いた図形と線、または Workstation で描いて Cmd に置いた図（下の「Workstation の図解を出す」） |
| confirm | 「確認です。〜よいですか？」のときのカード | Ray の確認待ち |

- 「おはよう」「朝のまとめ」で、天気 → 今日の予定 → 近い期限 を続けて見せます（Claude を呼ばない。上の「Ray から声をかける」）
- 声での操作（Claude を呼ばずにすぐ動く）：「次」「戻って」「もう一回」「大きく」「小さく」「閉じて」。話している途中はキーを押せば止まります
- 長い返事は、「続き」「次」と言わなくても最後の場面まで進みます（`auto_continue = false` で、6文で止めて「続き」を待つ以前の動きに戻せます）
- ウェブページの写真は playwright が入っているときだけ撮ります（無ければ引用カードだけ）。ブラウザは1つだけ起動して使い回し、5分使わなければ閉じます：
  ```sh
  pip install playwright && playwright install chromium
  ```
- 天気の場所は `config.toml` の `[weather]`（`place`・`latitude`・`longitude`）で変えられます

しくみ：Claude Code の返事の中の `@画面 種類 {JSON}` の行で場面を区切り、その下の文を読み上げます（指示の行は読み上げない）。場面はまとめて読み上げの順番待ちに入れ、次の場面の声は今の場面を話している間に作っておきます。画面は、その場面の声が鳴り始めたときに切り替わります（場面の間に間があかない）。グラフやカレンダーの中身は Ray が Cmd から集めるので、Claude が大きなデータを書く必要はありません。

## Workstation の図解を出す

Workstation の「図解」と同じ見た目の図を、Ray の画面に出せます。描く部分は Workstation の `src/renderer/diagram-draw.js` をそのまま写して使っています（`ray/ui/vendor/`。ネットからは読みません）。

- **Claude が描く**：`@画面 diagram {"title": "…", "nodes": [...], "edges": [...], "highlight": ["図形の id"]}`。書き方は Workstation の図のファイル（`*.diagram.json`）と同じです（Workstation の `src/main/diagram-guide.md`）。`x`・`y` を省くと、線のつながりにそって自動で並びます。構成図やデータベース・ER図のように Mermaid では描きにくいものは、こちらを使います
- **持ち主の図を出す**：「レイの構成の図を見せて」のように言うと、Workstation で描いて Cmd に置いた図（`*.diagram.json` と `*.mmd`。多くは `図解/日付/` の中）を名前で探して出します。`@画面 diagram {"name": "レイの構成", "highlight": ["route"]}`（場所で指すなら `"file": "図解/2026-11-27/レイの構成.diagram.json"`）
  - 名前は「同じ」→「含む」の順に探し、同じなら新しいものを使います。Cmd の外と、`.` で始まるフォルダは見ません
  - 貼った画像（`名前.assets/`）も出します（合わせて 4MB まで）
- 色：neon（暗い画面）では Workstation の色を暗い画面に合う色に置きかえ、blueprint（明るい画面）では Workstation の色のままです
- Mermaid の図（`code`）は、これまでどおり使えます

Workstation 側で図の描き方が変わったら、写し直します（Workstation をクローンした場所を渡す）：

```sh
python -m ray --sync-workstation ~/WORKSTATION
```

`diagram-draw.js` と Mermaid（`mermaid.min.js`）はそのまま、アイコン（Lucide）は図で使うものだけを `diagram-icons.js` に写します。

## 効果音

近未来のホログラムの画面のような電子音を鳴らします。音のファイルは持たず、`ray/sfx.py` が Python だけで合成します（映画などの音は使っていません）。最初の起動で1秒ほどかけて作り、次からは作っておいた音を使います。

SF らしさは、次の要素を組み合わせて出しています（映画の HUD の録画の分析と、この種の音の定番から）。

| 要素 | 作り方 |
|---|---|
| 金属的で、この世のものでない響き | FM 合成で、整数でない倍音にする |
| 光がちらつく感じ | 20 Hz 前後の速い音量のゆれ（トレモロ） |
| きらめき・厚み | 少しずらした2つの音のうなり |
| デジタルの粗さ | ビットクラッシュ（音の段を粗くする） |
| データを処理している感じ | ランダムな高さの短い粒を速く並べる |
| 画面が「ズッ」と開く感じ | 共鳴の強いフィルターを、ノイズに対して速く動かす |
| カチッという立ち上がり | 録画では 2.7 秒に14回。短いクリックを要所に置く |
| ずっと鳴っている高い電子音 | 録画では 6〜10 kHz に持続音。起動の最後に細く残す |
| グリッチ | ごく短い切れ端を3回くり返す |
| 空間に投影された広がり | 左右に跳ねるディレイと、残響 |

音の手ざわりは「カチッ」ではなく「ファン」にしています。立ち上がりを丸くし（30〜120 ミリ秒かけてふくらむ）、明るさ（倍音）がふくらんでから閉じていくように動かし、同じ高さの息の音を重ねて、全体の高いところを削り、残響を多めにしています。クリックとグリッチは使っていません。

| 音 | 鳴るとき |
|---|---|
| 起動（約3秒＋響き） | Ray を起動したとき。低いうなりがふくらみ、空気が吸い込まれ、「ファーン」と和音が開いたところで「レイです」と名乗る |
| 聞き始め | キーを押したとき・ウェイクワードで呼ばれたとき。2つの粒が上がり、2つ目が逆さに戻る（短く軽く） |
| 聞き取れた | 文字にできて、考え始めたとき。データの粒が3つ走り、その一つが逆さに戻って、粗いデジタルの尾を引く。ほかの3つのお手本 |
| 開く | 画面（カード）を出すとき。4つの粒が下から上へ走り、最後の一つが逆さに戻って粗い尾を引く。音は左から右へ動く。同じ種類の画面が続く間は鳴らさない |
| 閉じる | 「閉じて」で画面を消したとき。4つの粒が上から下へ走り、最後の一つが逆さに戻って粗い尾を引く。音は右から左へ動く |

起動以外の4つは、響きの尾まで含めて 0.5 秒で終わる、さりげない音です。楽器のように音符から音符へ跳ねると近未来感が消えるので、決まった高さを持たない音で作っています（共鳴フィルターが、息と金属的な FM の混ざった音を一気に通り過ぎる。リングモジュレーションで少しざらつかせる）。フィルターの行き先は 2 kHz 前後までにし、大きさも起動より 6〜9 dB 小さくしています。

4つとも「聞き取れた」と同じ作りにそろえ、粒の並び（上がる・下がる）と数・速さで区別しています。起動と同じデータの粒（金属的な FM の短い音）に、グリッチ（逆再生と、一瞬のデジタルの粗さ）を入れています。切れ目は数ミリ秒でなめらかにつないで、「カチッ」にならないようにしています。

起動以外の4つは、響きの尾まで含めて 0.5 秒で終わる、さりげない音です。高さは 330〜660 Hz に抑え、大きさも起動より 6〜9 dB 小さくしています。

`config.toml` の `[sfx]` で、`enabled = false` で止められ、`volume`（0〜1）で大きさを、`pitch` で音の高さを変えられます（0.5 が今の高さ。小さいほど低い）。

## ウェイクワード（任意）

声で呼ぶには、openWakeWord のモデルが必要です。「レイ」のような日本語の呼び名は用意されていないので、自分で作ります。

すぐ試すなら、openWakeWord に最初から入っている英語の呼び名が使えます（`model = "hey_jarvis"`。ほかに `alexa`・`hey_mycroft`・`hey_rhasspy`）。最初の起動でモデル（数MB）を取ってきます。

1. `pip install openwakeword`
2. openWakeWord の学習用ノートブック（Google Colab で無料で動く）で「レイ」を学習し、`.onnx` を `~/models/ray.onnx` に置く
3. `config.toml` の `[wake]` を `enabled = true`、`model = "~/models/ray.onnx"` にする

呼ばれたら円が緑になり、黙るまで（1.2秒）聞き取ります。誤反応が多ければ `threshold` を上げてください。ウェイクワードを使っている間はマイクが開きっぱなしになりますが、音は Mac の外には出ません。

## Codex（コードの係・任意）

Codex CLI を、Claude と併用する「第二の脳」として使います（決めたことは Cmd の `Notes/音声連携.md`）。

1. `brew install --cask codex` して `codex login`（ChatGPT のアカウント）
2. `config.toml` に `[codex]` `enabled = true`

- コードの生成・修正・レビューの話（コード・関数・バグ・テスト・レビューなど）は、Claude より先に Codex へ回します。Codex が答えられなければ Claude へ
- Claude が5時間の上限を返したら、その話を Codex が受けます。そのあと30分（`limit_rest_min`）は Claude を起こさずに Codex へ
- お金・仕事・予定・メモの話は、Codex には渡しません。コードの話でも、上限のときでも同じです。上限のときは「上限が戻ってから聞いてください」と言います
- Codex に渡すやり取りは、Claude が答えたもの（持ち主のデータを含みうる）を除いた分だけです
- 呼び方は `codex exec`（非対話）で、最終回答を標準出力から取ります。作業するのは Ray のリポジトリだけ（`-C`）。Cmd は渡しません
- 返事は3文まで・記号なし・日本語だけ、と指示しています
- `~/.codex/config.toml` は読みません（`user_config = false`）。ほかの用途の既定モデル（Ollama など）を持ち込まないためです
- 会話の記録には `brain: codex` と、回した理由（`usage.why`：`code` か `claude_limit`）が残ります

## n8n から話させる（任意）

n8n のワークフロー（定時・メールが届いたとき・Webhook など）から、Ray に文を送って読み上げさせ、画面にも出せます。

1. `config.toml` に `[notify]` を書く：`enabled = true`、`token = "（16文字以上の合言葉）"`。合言葉は `python3 -c 'import secrets; print(secrets.token_urlsafe(24))'` で作れる
2. n8n で HTTP Request ノードを置く
   - Method：`POST`。URL：`http://127.0.0.1:8765/notify`
   - Header：`X-Ray-Token` に、合言葉を入れる
   - Body：JSON で `{"title": "天気", "text": "明日は雨です。傘を持ってください。"}`
3. 例のワークフローは `examples/n8n/ray-notify.json`（毎朝8時）。n8n の画面で「Import from File」して、合言葉を入れ替えて使う

- `text` は Claude の返事と同じ形です。`@画面 steps {"title": "…", "steps": ["…"]}` の行を入れると、図やスライドも出ます。Claude も Gemini も呼びません
- 会話の途中に届いたら、終わるまで待ってから話します（10分より長く待ったら捨てます。`wait_sec`）。続けて届いたら順番に話します
- 話している途中でキーを押せば、いつもどおり止まります
- 話した内容は、会話の記録（`Data/ray/`）に `brain: n8n` として残ります
- 受け口は Mac の中（127.0.0.1）だけです。n8n を Docker で動かすと届かないので、Mac で直接動かしてください（`n8n start`）
- n8n をサーバーに置くときは、Tailscale を通して `[notify] listen` で受けます。手順は [`n8n-server/README.md`](n8n-server/README.md)（外から受けるのは `/notify` だけで、状態の画面は見せません）
- 合言葉が違うもの、JSON でないものは受け付けません（ブラウザで開いたページから、勝手に話させられないようにするため）
